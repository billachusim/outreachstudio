
# Consolidate to a single workspace (nachusim@gmail.com)

## The situation

The app has two user accounts in the database, and I mistakenly treated them as two real workspaces this session:

- **KEEP — `nachusim@gmail.com`** (`3019e20e-…`) — your real account. Last sign-in Jun 14. Owns 8,583 leads, 6,550 pitches, 108 campaigns, the Gmail connection, and all of this session's curated offerings/templates/rules.
- **DELETE — `tester_outreach@mailinator.com`** (`e016e154-…`) — a tester account created Apr 22, signed in exactly once, never used since. Has no Gmail connection (so its 1,519 "pitches" never actually reached anyone). Its 82 campaigns and 412 intel items were generated by background cron jobs running indiscriminately for every user, not by you.

Nothing in Account B is unique or worth merging — its offerings/templates are subsets of what's already curated in A, and its intel/leads come from the same auto-fetch sources A uses.

## What I'll do

### 1. Purge all data belonging to the tester account
Delete every row in every `public` table where `user_id = 'e016e154-…'`. This covers:
`campaigns`, `campaign_runs`, `run_events`, `pitches`, `pitch_events`, `pitch_sequences`, `leads`, `lead_fetch_runs`, `intel_items`, `intel_sources`, `offerings`, `templates`, `channel_accounts`, `channel_messages`, `chat_conversations`, `chat_messages`, `agent_memories`, `aggregator_performance`, `daily_briefings`, `social_drafts`, `profiles`.

Order respects FK dependencies (children before parents).

### 2. Delete the tester auth user
Remove the row from `auth.users` for `e016e154-…` so it can never sign in again and so future cron jobs can't accidentally seed data back into it.

### 3. Scope cron jobs to the real account only
The three cron jobs (`campaign-tick-every-2min`, `follow-up-tick-every-10min`, `auto-launch-top-triggers-daily`) loop over users. With Account B gone they'll naturally only act on A, but I'll also audit the edge functions to confirm none of them hardcode or special-case `e016e154-…`.

### 4. Verify the cleanup
Re-run the per-`user_id` row count query — every table should show only `3019e20e-…` afterwards. Confirm the three cron jobs are still scheduled and active.

## What stays untouched

- All of Account A's data (leads, campaigns, intel, offerings, templates, Gmail connection, pitches history).
- This session's work: the 2 new offerings, the 2 new templates, archived items, paused/archived old campaigns, and the new cron rules.
- Schema, RLS policies, edge functions, and all UI code.

## After this is done

You'll have exactly one workspace — `nachusim@gmail.com` — and nothing in the system will ever spawn data into a second account again. Tomorrow morning's 07:00 WAT auto-launch will run only for you.

- Deletes run via the data tool (not migrations), in a single transaction-style batch ordered by FK dependency.
- `auth.users` deletion cascades through `profiles` via the existing FK, but I'll delete `profiles` explicitly first to be safe.
- No schema changes, no policy changes, no code changes required.
